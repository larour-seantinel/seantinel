## Insights and Decisions — ISSM native build / APK packaging

- 2026-10-22: ISSM native build on Android: all Termux deps installed (openmpi, openblas, hdf5, netcdf-c, autoconf, automake, libtool, cmake, flang). No gfortran in Termux — use `flang` (LLVM Fortran, aarch64-android30). Need custom PETSc install script with `FC=flang`.
- 2026-10-22: PETSc 3.25.4 successfully built and installed on Android/Termux at `~/issm/externalpackages/petsc/install/`. MPICH 5.0.0 built separately at `~/issm/externalpackages/mpich/install/`. MUMPS 5.8.2 built manually inside PETSc's arch dir. Key script: `externalpackages/petsc/install-3.25-android.sh` + `patch-mpich-android.sh`. Final PETSc configure uses `--with-mpi-dir` + `--with-mumps-include/lib` instead of `--download-mpich/mumps`.
- 2026-10-22: When `--with-mpi-dir` is used in PETSc configure, do NOT also specify `FC=flang` — PETSc refuses both together. The MPICH wrappers (mpif90/mpicc) already encode the compiler.
- 2026-10-22: ISSM Jenkins configs are the build reference. Closest targets: `mac-silicon-python` (aarch64) and `ross-debian_linux-python` (Linux). Standard external package order: autotools → cmake → petsc → triangle → shell2junit. PETSc script downloads its own MPICH, MUMPS, METIS, ScaLAPACK, BLAS/LAPACK.
- 2026-10-22: Triangle `install-linux.sh` works on Android as-is — plain gcc, no Fortran, no patches needed. Built to `~/issm/externalpackages/triangle/install/lib/`.
- 2026-10-22: ISSM configure requires `bash ./configure` (not `./configure`) — shell compatibility issue on Android. Also requires numpy: `pip install numpy` before configure.
- 2026-10-22: ISSM configure does not recognize `--without-matlab` flag — prints a warning but MATLAB is off by default anyway. Warning is harmless.
- 2026-10-22: ISSM configure succeeded on Android with flags: `--with-petsc-dir`, `--with-mpi-dir`, `--with-triangle-dir`, `--with-python-version=3`, `--without-fortran`.
- 2026-10-22: ISSM `make -j5` started and produced 53 .o files before session crash. Build is resumable — running `make -j5` again from `~/issm` will continue where it left off.
- 2026-10-23: `python-scipy`, `python-numpy`, `libhdf5`, `netcdf-c`, `python-netcdf4` all already installed via Termux `pkg`. Verify any Python dep with `pkg list-installed | grep <name>` before pip. Pip on Termux triggers Android OOM-kills (signal 9) for anything with native code.
- 2026-10-23: Android bionic uses linker namespaces (Android 8+). `dlopen` of a Python wrapper `.so` resolves symbols only through its own `DT_NEEDED` chain — not globally. `ctypes.CDLL(..., RTLD_GLOBAL)` doesn't make earlier-loaded libs visible to later dlopens. The only reliable fix is to put the symbol provider into the wrapper's own NEEDED (patchelf) or into the wrapper's dependency chain.
- 2026-10-23: Running `test101.py` end-to-end from Python requires `PYTHONSTARTUP=$ISSM_DIR/src/m/dev/devpath.py` (sets sys.path), plus `LD_LIBRARY_PATH` with triangle+issm lib dirs, plus a working `issm.exe`. The Python layer, mesh triangulation, parameterization and solve-queue script generation all work. Only the native solver run segfaults, due to the MPI double-link.
- 2026-10-23: ISSM generates a `test101.queue` shell script under `~/issm/execution/test101-<timestamp>/` that calls `mpiexec -np 2 issm.exe ...`. `mpiexec` resolves to Termux's OpenMPI launcher by default — mismatched with MPICH-linked bits of ISSM. Must prepend MPICH's bin dir to `$PATH` for both build AND run.
- 2026-10-23: `exec(open('test101.py').read())` inside a wrapper script makes `__file__` resolve to `<string>`, which breaks ISSM's solve.py (it uses the model name derived from the script name to find input/output files). Use `runpy.run_path('test101.py', run_name='__main__')` or just `python3 test101.py` with proper PYTHONPATH.
- 2026-10-23: Bionic resolves `DT_NEEDED` entries by **filename**, not SONAME. If a lib's NEEDED is `libmpi.so` and MPICH's install dir (which contains a `libmpi.so` symlink with internal SONAME `libmpi.so.12`) is first in `LD_LIBRARY_PATH`, MPICH wins — the SONAME mismatch is ignored. Useful workaround for ScaLAPACK pulling in OpenMPI's `libmpi.so` without rebuilding.
- 2026-10-23: MPICH's `mpicxx` wrapper writes `final_cxxflags=" -std=gnu++20 -fPIC -O3"` into the install (line 299 of the wrapper script, generated at MPICH configure time). Overridable by editing the wrapper directly — no reconfigure needed. For ISSM, C++17 is required because `std::vector<Observation>` with a forward-declared `Observation` violates C++20's complete-type requirement for destructor instantiation.
- 2026-10-23: Full test 101 runs end-to-end on Android/Termux with `np=1`: FemModel init ~62 ms, solver ~61 ms. Env needed: `ISSM_DIR`, `PATH` with MPICH bin first, `LD_LIBRARY_PATH` with MPICH lib + triangle lib + issm lib first, `PYTHONPATH` includes `src/m/dev`. Launch via `python3 -c "import devpath; import runpy; runpy.run_path('test101.py', run_name='__main__')"`.
- 2026-10-23: MPICH ch3:sock rebuild path: reconfigure the tarball under `~/issm/externalpackages/petsc/src/arch-android-c-opt/externalpackages/mpich-5.0.0/` with `--with-device=ch3:sock --prefix=~/issm/externalpackages/mpich/install`, re-apply the Android patches (`mplconfig.h` + `mpichconf.h`) to the fresh build dir, `make -j && make install`. After install, re-patch `mpicxx` wrapper line 299 (`gnu++20` → `gnu++17`) — the install overwrites it. Confirmed np=2 works on 10-core ARM (4× A520 + 6× A720).
- 2026-10-26: Permanent MPI-leak fix — `patchelf` is available on Termux (`pkg install patchelf`). Replace OpenMPI NEEDED on PETSc-side libs: `patchelf --replace-needed libmpi.so libmpi.so.12 libscalapack.so.2.2.3` and the same on `~/issm/bin/issm.exe`, plus `patchelf --remove-needed libopen-rte.so --remove-needed libopen-pal.so` on issm.exe. Also replace stale nemesis-era MPICH SOs under `petsc/install/lib/` with the ch3:sock rebuilt copies from `mpich/install/lib/`. After this, test 101 passes with LD_LIBRARY_PATH that does NOT include `mpich/install/lib`.
- 2026-10-26: WebView + JNI integration pattern for Termux-built APKs. In `MainActivity`, `webView.getSettings().setJavaScriptEnabled(true)` and `webView.addJavascriptInterface(new NativeBridge(), "Native")`; `NativeBridge` methods are called from JS as `window.Native.foo()`. Lib loading goes in a method body (not static init) and returns a status string — gives you a working debug channel without a USB cable or adb logcat. Native code in `jni/*.c` compiled with `clang -c -fPIC`, linked `clang++ -shared`; JNI entry name `Java_<package>_<class>_<method>` using underscores for dots. See `android-spike/` for a working end-to-end minimal example.
- 2026-10-26: **Milestone — full ISSM native stack runs inside a stock Android app.** `android-spike/build/spike.apk` loads 15/15 libs on-device. Native `nativeHello()` returns `MPI: MPICH Version: 5.0.0` + `ISSM dlamch('E') = 1.110223e-16`. `libissmstatics.so` provides 5 symbols (4 statics + `ApiPrintf`).
- 2026-10-26: Running a full ISSM `.so` stack from inside an Android APK: 13 shared libs (openblas, libc++_shared, libz, libandroid-shmem, mpi/mpicxx/mpifort, metis/parmetis, slatec, scalapack, petsc, ISSMCore, +issmstatics +spike). All renamed to plain `lib*.so` names and patchelf'd so SONAME + every NEEDED entry uses plain names (Android PackageManager drops `lib*.so.N` style files silently). Load order from Java: deps first, then dependers. `libissmstatics.so` MUST load before `libISSMCore.so` and MUST be in libISSMCore's NEEDED (plain Java load-ordering is not enough — bionic namespaces).
- 2026-10-26: Semi-automated APK install from Termux (no adb needed): `cp build/spike.apk ~/storage/shared/Download/spike.apk && termux-open ~/storage/shared/Download/spike.apk` fires Android's package installer directly. Key gotcha: `termux-open` on an APK in Termux's private storage silently does nothing — the installer app runs as a different UID and can't read 0600 files. Must copy to shared storage first. Self-signed APKs with the same cert install as updates (no uninstall step).
- 2026-10-26: Minimal Android APK buildable in pure Termux. Toolchain: `pkg install aapt aapt2 ecj apksigner dx openjdk-25`. Critical gotchas: Termux's bundled `android.jar` is a STUB — use a real one from `Sable/android-platforms`. `openjdk-21` is broken (ProtoLogNative abort) — use `openjdk-25`. The `ecj` wrapper hardcodes `-7` compliance + stub android.jar; invoke the jar directly via `dalvikvm`. `keytool` also crashes under openjdk-21 — skip the keystore entirely and use openssl → apksigner.
- 2026-10-27: **Milestone — test101 StressbalanceSolution runs end-to-end inside the Android APK (np=1, in-process via JNI).** Pattern: package `test101.bin` + `test101.toolkits` as APK assets; Java copies them to `getFilesDir()/test101/`; JNI function mirrors `issm.cpp`'s `main()` body (EnvironmentInit → `new FemModel(argc, argv, comm)` → `femmodel->Solve()` → `OutputResultsx` → `CleanUp` → `EnvironmentFinalize`), with stdout/stderr redirected via `dup2` to a file in filesDir. On-device timings: FemModel init 37 ms, Solve 18 ms.
- 2026-10-28: **Milestone — live native solve drives the WebView plot inside the APK.** Full pipeline: button tap → `System.loadLibrary(...)` all 15 libs → JNI runs StressBalance → Java reads `test101.outbin` → base64 via `@JavascriptInterface` → JS DataView parses the 15 ISSM records → `md.results.StressbalanceSolution` replaced in-place → Three.js mesh re-rendered. ISSM `.outbin` format: `int32 length` (-1 or EOF), name bytes (incl. trailing `\x00`), `float64 time`, `int32 step`, `int32 type` (1=double vec, 2=char, 3=double matrix with int32 N dim, 4=int matrix), `int32 M`, then payload.
